# Handoff (v5): the agent inside Orbita's CRM mockup

> For whoever continues this in Claude Code. v3 (Teams, 8 fields) is preserved in `mockups/mockup-call-to-crm_2026-10-27.html`.

## Goal
One loop that runs for real: a sales conversation (a transcript from any notetaker, or a WhatsApp export) is dropped or pasted → the agent attributes it to the right opportunity (or proposes a new one) → it proposes **22 fields** (MEDDPICC qualification included), each with a transcript quote → per-field permissions decide what is written at once (Always allow, with Undo), what waits for the seller (Needs approval) and what is left alone (Never) → every step is in the activity log. **Explore** answers questions about the pipeline from the CRM.

Out of scope (do not build): pre-meeting briefings, solution recommendation, proposals and pricing, contact editing, manager dashboards.

## What exists (use it, don't rewrite it)
- `agent/field_schema.json`: every field rule, the MEDDPICC letters and questions, the default permissions. Change a field here, then run `node scripts/build_data.mjs`.
- `agent/core.mjs` (pure rules), `eval/score.mjs` (pure scorer), `agent/explore.mjs` (pure Explore): run identically in the CLI, the server and the mockup page (embedded verbatim by `mockups/dados/render_capstone.py`). Never port them by hand.
- `agent/pipeline.mjs`: prompt (cached static block + compact message), Claude through `@anthropic-ai/sdk` with structured outputs (`callJson`), usage and cost in the log; `--file` reads any transcript.
- `mockups/server.mjs`: live runs and live Explore for the page; the key from `capstone/.env`.
- `samples/`: the eleven conversations as files to drop (generated by `build_data.mjs`, each checked to read back to the same text).
- Mockup generator in `mockups/dados/` (see `mockups/LEIAME.md`); gate: `python mockups/dados/qa_capstone.py`.

## Hard rules (do not break them for convenience)
- Nothing writes to the CRM except `applyApprovedFields`: for the fields the seller decided, or that are under Always allow. A contradiction with an approved value always waits for the seller. Creating a client or an opportunity goes through the same function, after the seller's decision or the creation permission.
- Never pass `eval/reference_outputs/` or `eval/expected_results.json` into a prompt.
- The validator runs on every live output. Never show raw model output to the seller.
- Explore sees only the opportunities the user can read (filtered on the server too).
- Transcripts are referenced in the run log, never copied into it.
- The demo video and the eval use synthetic data only. No prototype jargon on screen (the gate checks it).
